# A-L-L-A-H Ecosystem — Core Foundation Charter

**Status:** DECIDED direction; detailed definitions remain under review.

## What the core is
The core is the stable meaning layer beneath the ecosystem—not a UI, framework, database, or repository layout. It defines purpose, product boundaries, canonical concepts, knowledge and evidence models, data ownership, publication rules, and constraints future software must preserve.

## Product constellation
- **ROCKSOUL DX:** private creation, personal research, memory, and creative workspace.
- **MoonWitness:** public-facing storytelling, witnessing, research, archive, and selected publication.
- **Master Docs / future Master Hub:** shared documentation authority and governed coordination layer.

These products are related but not interchangeable. Shared canon does not imply shared storage, permissions, UI, or release lifecycle.

## Core knowledge model
Preserve distinctions between owner statements, source reports, direct observations, remembered dreams, research, interpretation, hypothesis, coincidence/personal meaning, fiction, humor/play, and unknowns. These labels must travel with content through search, summarization, editing, and publication.

## Canon model
Canon is owner-governed. AI may organize, compare, and suggest, but cannot silently rename entities, invent relationships or chronology, decide unresolved meanings, merge contradictions, or upgrade proposals into confirmed records. Meaningful canon items need stable identity, exact name, definition, source, author, status, privacy classification, and history where available.

## Privacy and publication
Private creation is the default. Publication is a separate explicit act that identifies selected content/assets, destination/audience, attribution/context, privacy review, owner approval, and a correction/retraction path. No automatic ROCKSOUL-to-MoonWitness synchronization.

## Human and AI authority
Humans define goals, approve canon, set access, and authorize consequential actions. Agents research, plan, draft, classify, and execute bounded tasks only within explicit permissions. Agents cannot grant themselves access or approve their own high-impact actions.

## Build sequence
**Meaning before model. Model before contract. Contract before code. Code before release.**
1. Establish exact meaning and product boundaries.
2. Define ontology, canon, provenance, and privacy.
3. Finalize product workflows and experience contracts.
4. Finalize data, API, task, knowledge, MCP, and agent contracts.
5. Resolve architecture decisions and test criteria.
6. Expand application and runtime only after these gates.

## Foundation acceptance
A new contributor or local AI agent must be able to answer from documents alone: what each product is/is not; where canonical definitions live; what is known versus interpreted/unknown; which data is private/internal/public; what can move between products and who approves it; which contracts govern each capability; which decisions are accepted/open; and what evidence marks work complete.
