## 3. Authority Hierarchy (Ecosystem vs. Repository)

Reconciling `A-L-L-A-H` ecosystem governance with MoonWitness repository governance requires a strict two-tier constitutional split so neither overrides the other out of scope:

1. **Tier 0 — `A-L-L-A-H` Ecosystem Constitution (`docs/constitution/` + Owner `@bjo163` Decisions):**
   - Owns cross-product vision, sacred/Low-Profile Tawhid boundaries, canon provenance (`CANON-PROVENANCE-CONTRACT.md`), and product boundaries (`ROCKSOUL DX` private desktop vs. `MoonWitness` public web).
   - Monorepo documents **MUST NOT** dilute or alter Tier 0 canon, privacy-by-default invariants, or the 4-line ROCKSOUL manifesto.
2. **Tier 1 — MoonWitness Repository Governance (`AGENTS.md`, `docs/governance/MW-GOV-DOC-001..005`, `ARCH-ADR-*` in `docs/architecture/`):**
   - Owns monorepo-wide Git branching (`dev`-only locally), workspace topology (`apps/{api,rocksoul,web}` per `ARCH-ADR-006`), Trust Zones A/B/C, quality gates (`scripts/gatecheck.mjs`), documentation lifecycle statuses, and validation enforcement.
   - Where absorbed Tier 0 or Tier 4 documents cite pre-consolidation multi-repo paths (`A-L-L-A-H/rocksoul-dx`, `ArsyBelovedLabs/*`, standalone `apps/mid`/`apps/igate`/`apps/memory`), Tier 1 (`ARCH-ADR-006`) governs monorepo workspace resolution.
3. **Tier 2–5 — Operational Engineering, Co-Located Engines/Apps/Packages, Frozen Blueprints, Historical Archives:**
   - Govern domain-local technical execution without contradicting Tier 0 or Tier 1 invariants.
