# MoonWitness Documentation Governance Contract

## 1. Purpose and Authority

This contract is the **primary documentation governance authority** for the `A-L-L-A-H/moonwitness` monorepo (`dev` branch).

MoonWitness is one product within the broader `A-L-L-A-H` ecosystem alongside `ROCKSOUL DX` and `A-L-L-A-H / Empire of the Light`. Because this repository consolidates active application workspaces, shared packages, host/data-plane services, constitutional ecosystem specifications, frozen Gen2 blueprints, sovereign research engines, and historical chronicle archives, documentation governance **MUST** operate across the entire monorepo **without forcing all documentation into a single directory**.

This contract establishes:

1. A unified contract hierarchy where specialized standards derive authority from this document.
2. Explicit reconciliation of pre-existing governance layers without creating competing systems or erasing historical provenance.
3. Unambiguous ownership, Single Source of Truth (SSOT) boundaries, lifecycle rules, evidence discipline, and AI agent compliance mandates.

When two documents conflict and no reconciliation ADR exists:

3. **Mandatory Visibility:** Never silently delete or flatten a conflicting specification. Record the conflict visibly and escalate to the owning human authority.

## 7. Mandatory AI Agent Compliance Rules

All autonomous and interactive coding agents (including Codex, Antigravity, Claude Code, Cursor, and local AI runners) **MUST** enforce the following ten rules whenever reading, authoring, or modifying documentation or code:

1. **Read Governance First:** Read root [AGENTS.md](../../AGENTS.md) and `docs/governance/DOCUMENTATION_GOVERNANCE_CONTRACT.md` before creating or modifying any documentation or architectural artifact.
2. **Inspect Existing Indexes Before Creating Files:** Check [DOCUMENT-INDEX.md](../constitution/GOVERNANCE/DOCUMENT-INDEX.md), [CONSOLIDATION-CATALOG.md](../CONSOLIDATION-CATALOG.md), [DOCUMENT-CATALOG.md](../blueprint/DOCUMENT-CATALOG.md), and `docs/architecture/` before authoring a new specification.
3. **Zero Duplicate Canonical Specifications:** Never author a competing contract, ADR, or governance rule when an authoritative document already owns that topic; link to the canonical authority instead.
4. **Never Silently Delete or Rewrite Historical Evidence:** Preserve `SUPERSEDED` ADRs, dated audits, upstream commit pins, character spelling variants, and unresolved conflicts (`#014` patch conflict, `RGBL/SRGBL` dual status).
5. **No Implementation Claims Without Code Evidence:** Never mark a requirement `IMPLEMENTED`, complete, or production-ready based solely on a roadmap checkbox, UI stub, blueprint YAML, or prior audit. Cite verified file paths, branch (`dev`), commit SHA, and executed test/gate results.
6. **Preserve Decentralized Ownership:** Place engine docs under `engines/<engine>/`, application docs under `apps/<app>/`, service docs under `services/<svc>/`, and repository-wide docs under `docs/`. Never force-migrate local docs into a single monolithic folder without an approved migration wave.
7. **Enforce Root Branch & Gate Precedence:** Obey root [AGENTS.md](../../AGENTS.md) (`dev`-only local checkout; zero extra local branches) over any conflicting instructions inside absorbed `engines/*/AGENTS.md` files.
8. **Maintain Indexes and Links Atomically:** When adding, renaming, superseding, or archiving a document, update all affected catalogs, indexes, and cross-links in the same change set.
9. **Respect Trust Zones and Sacred Guardrails:** Never cross Trust Zones (`Zone A` Cloud/VPS, `Zone B` ROCKSOUL Local, `Zone C` `services/memory`), never expose private data by default, and strictly enforce Low-Profile Tawhid and Creator–Human boundaries.
10. **Report Conflicts Rather Than Inventing Decisions:** When encountering contradictory contracts, unratified canon, or missing owner approvals, stop and report the exact conflict and options instead of fabricating an accepted decision.
