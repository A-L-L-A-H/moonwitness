# MoonWitness Documentation Validation Strategy

## 1. Validation Design Principles

1. **Zero Extra Dependencies:** Every automated documentation check uses Node.js (`>=20`) standard library modules (`node:fs`, `node:path`), Prettier (`pnpm format:check`), and Git (`git diff --check`), adding zero npm packages or Python/Ruby toolchains.
2. **Strict Gate State Fidelity:** Automated checks integrate with [scripts/gatecheck.mjs](../../scripts/gatecheck.mjs) using `PASS`, `FAIL`, `BLOCKED`, or `NOT APPLICABLE`.
3. **Automation vs. Judgment Split:** Deterministic syntax, metadata, encoding, and link invariants belong to CI; semantic accuracy, canon integrity, and architectural approvals belong strictly to human review.

## 2. Ten-Rule Validation Matrix

| ------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `DOC-VAL-001` | **Broken Internal Links**               | Parse `[label](target)` outside fenced and inline code spans; ignore `http(s)://`, `mailto:`, `#anchor`; assert resolved repo-relative path exists on disk.                                                                                                                                                                              | Verify anchor fragments (`#section`) and cross-repo URLs point to intended concepts.                                                          | `FAIL` on active `AGENTS.md`, `README.md`, `docs/{governance,architecture,engineering,dna,ui}/`, `apps/*`, `packages/*`, `services/*`, `cp/*` |
| `DOC-VAL-002` | **Missing Index Entries**               | Verify every file in `docs/{governance,architecture,engineering,dna,ui}/` is referenced by its Level 1 hub index.                                                                                                                                                                                                                        | Confirm newly created engine/app docs are added to their Level 2 `README.md`.                                                                 | `FAIL` on `docs/governance/` & `docs/architecture/`                                                                                           |
| `DOC-VAL-003` | **Invalid Metadata & Encoding**         | Reject NUL (`\x00`) bytes and UTF-16 BOMs (catching defects like `WORK_PLAN.md`); enforce single `# ` H1 heading; verify `title`, `status`, `owner`, `last_reviewed`, and `version` (for contracts) in YAML frontmatter.                                                                                                                 | Confirm `owner` matches the real accountable maintainer and `last_reviewed` reflects an actual review.                                        | `FAIL` on active `docs/governance/` & new ADRs/contracts                                                                                      |
| `DOC-VAL-004` | **Conflicting Canonical Docs**          | Enforce unique `contract_id` across `docs/governance/*.md` and check `BLUEPRINT-LINT-CONTRACT-V1.yaml` unique-owner assertions on blueprint changes.                                                                                                                                                                                     | Human Architect reviews whether a new spec duplicates an existing SSOT in [DOCUMENTATION-AUTHORITY-MAP.md](./DOCUMENTATION-AUTHORITY-MAP.md). | `FAIL` on duplicate `contract_id`; Human Gate for semantic overlap                                                                            |
| `DOC-VAL-005` | **Missing Ownership**                   | Assert non-empty `owner` metadata on all newly authored normative docs (`TBD` permitted temporarily for `DRAFT`/`PROPOSED`; forbidden for `ACCEPTED`).                                                                                                                                                                                   | Maintainer validates accountability transfer when creating new workspaces or packages.                                                        | `FAIL` if missing or `TBD` on `ACCEPTED` doc                                                                                                  |
| `DOC-VAL-006` | **Invalid Lifecycle Status**            | Enforce the 8-status allowlist (`DRAFT`, `PROPOSED`, `ACCEPTED`, `PARTIALLY_IMPLEMENTED`, `IMPLEMENTED`, `SUPERSEDED`, `ARCHIVED`, `REJECTED`) on active governed docs.                                                                                                                                                                  | Owner (`@bjo163`) approves transitions into `ACCEPTED` or `SUPERSEDED`.                                                                       | `FAIL` on invalid status token                                                                                                                |
| `DOC-VAL-007` | **Orphan Documents**                    | Build inbound-link graph from Level 0/1/2 indexes; flag non-archive docs in `docs/` and `research/` with zero inbound links.                                                                                                                                                                                                             | Decide whether an orphan doc belongs in an active index or `ARCHIVED`.                                                                        | Advisory warning in Phase 1; `FAIL` post-Wave 4                                                                                               |
| `DOC-VAL-008` | **Stale Implementation Claims**         | Scan active `docs/{architecture,engineering}/` for backticked workspace paths (`apps/<x>`, `packages/<x>`, `services/<x>`, `cp/<x>`); flag nonexistent paths (e.g., `apps/a-l-l-a-h`, `apps/mid`, `apps/igate`, `apps/memory`) unless inside explicit `Superseded` / `Historical` sections.                                              | Human reviewer audits cited tests, CI logs, and runtime endpoints before allowing `IMPLEMENTED` status.                                       | `FAIL` on nonexistent active workspace path post-Wave 1; Human Gate for runtime truth                                                         |
| `DOC-VAL-009` | **Missing References to Accepted ADRs** | Verify ADR citations in new `docs/architecture/` and `docs/engineering/` files use disambiguated namespaces (`ARCH-ADR-NNN`, `CONST-ADR-NNNN`, `BP-ADR-NNN`, etc.) and resolve to valid files.                                                                                                                                           | Reviewer checks architectural PRs for missing ADR updates when Trust Zones, topology, or APIs change.                                         | `FAIL` on broken ADR path; Human Gate for missing ADR coverage                                                                                |
| `DOC-VAL-010` | **Governance Violations**               | Enforce Tier 1 root allowlist (reject unapproved root `.md` files beyond `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `WORK_PLAN.md`), reject quarantined hallucinated repo strings ([CODEX §VII.1](../MASTER-CANON-CROSS-REPO-CODEX.md)), run Prettier (`pnpm format:check`), `git diff --check`, and `stepSecretScan`. | Human review for Trust Zone A/B/C isolation, Low-Profile Tawhid guardrails, and canon provenance.                                             | `FAIL` on secret leak, format drift, root clutter, or quarantined citation                                                                    |

## 3. Integrated Validation Implementation (Wave 5)

Implemented on `dev` without adding any external package dependency:

1. **Zero-Dependency Script ([scripts/doc-check.mjs](../../scripts/doc-check.mjs)) & Unit Suite ([scripts/doc-check.test.mjs](../../scripts/doc-check.test.mjs)):** Enforces `DOC-VAL-001..010` across active documentation scopes (`/` root allowlist, `docs/governance/`, `docs/architecture/`, `docs/engineering/`, `docs/dna/`, `docs/ui/`, `research/`, `apps/*/README.md`, `packages/*/README.md`, `services/*/README.md`, `cp/arsy/README.md`) while keeping read-only archives (`docs/legacy-harvest/`, `content/chronicles/`, `engines/chronicle-os/`) exempt from active metadata rewrites.
2. **Package, Gate & CI Integration:**
   - `"docs:check": "node scripts/doc-check.mjs"` and `"docs:test": "node --test scripts/doc-check.test.mjs"` added to root [package.json](../../package.json).
   - `docs-governance` (`pnpm docs:check`) and `docs-tests` (`pnpm docs:test`) integrated into `quickSteps` and `localSteps` inside [scripts/gatecheck.mjs](../../scripts/gatecheck.mjs).
   - `Docs Governance` running `pnpm docs:test` and `pnpm docs:check` added to the `verify` job in [.github/workflows/ci.yml](../../.github/workflows/ci.yml).
