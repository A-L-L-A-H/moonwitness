# 00 — Start Here

## Project name

**R!OT OS** — a premium admin, analytics, and operations template powered by **R!OT UI**, its reusable design system.

## The mission in one sentence

Transform the current application into a maintainable pnpm monorepo and an unmistakable premium template whose visual language is **CHAOS BRUTAL GRUNGE GEN Z FUNKY**: underground poster energy, brutal editorial typography, xerox textures, comic/manga artwork, industrial control-room structure, acid color, and original generative visuals.

## Read and obey

Read every numbered `.riot-ai` document before broad implementation. `AGENTS.md` defines the safety and execution rules. `10-TODO.md` is the implementation ledger. `11-ASSET-MANIFEST.json` is the target visual inventory.

## Working interpretation

- **Vuexy is a product-category reference, not a source to copy.** Learn from the completeness expected of a premium admin template—multiple layouts, app pages, dashboards, settings, documentation, and polished component coverage. Do not copy its source, brand, exact UI, illustration, or asset.
- **R!OT is not a generic dashboard with a grunge background.** The identity must be embedded into typography, composition, controls, charts, illustrations, page transitions, empty states, and the artwork system.
- **Chaos is controlled.** Navigation and data remain easy to scan. The strongest visual disorder is concentrated in hero zones, illustrations, section transitions, badges, decoration, and selected states.
- **Artwork is a first-class product feature.** Build an asset library and a reproducible production pipeline, not a handful of random decorative images.
- **Shared components are mandatory.** A module may have a different composition or variant, but must not clone common UI markup and styles.

## Priority order

1. Preserve existing application behavior and establish a reliable build.
2. Establish monorepo boundaries and a single design-token source of truth.
3. Establish the shared UI, layout, navigation, chart, form, and artwork systems.
4. Make the R!OT DNA unmistakable across the whole product.
5. Migrate existing modules without dropping their features.
6. Complete the demo, starter, documentation, and quality gates.

## Definition of an honest completion

A task is complete only when its implementation exists, its usage is demonstrated where relevant, and the required checks pass. A prompt, screenshot, empty folder, mock component, or TODO note alone is not implementation evidence.
