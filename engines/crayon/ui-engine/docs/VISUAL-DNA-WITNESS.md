# Visual DNA Experiment — Witness History

CRAYON history must not collapse into a generic activity feed.

## Semantic structure

A witness-history representation has four distinct meanings:

- **prediction** — what the transition expected before execution;
- **observation** — what was actually reported and by which source;
- **reconciliation** — later evidence used to establish or challenge an outcome;
- **witness** — immutable historical assessment at the time of the action.

Retry/reconciliation advice is a derived actionability state, not another historical fact.

## Representation constraints

1. Current truth and history must remain distinguishable.
2. Prediction must not visually acquire the authority of observation.
3. Unknown/conflicted observations remain incomplete/conflicted rather than red failure badges by default.
4. Trace strength may increase persistence/salience but may not fabricate certainty.
5. Correction/rollback/follow-up is a new trajectory and witness, never an edit to the original event.
6. Compact/zoomed representation may summarize detail, but unresolved outcome and material witness status cannot disappear.

## Cross-domain evidence

The temporal falsification suite uses the same Snapshot → RIR → Inspector history grammar for recursive deletion, irreversible communication, approval chains, partial deployment, and AI-proposed changes. A witness convention is not accepted if it only makes sense for transaction history or logs.

## Rejection criteria

Reject designs that are primarily:
- chronological notification feeds;
- green/red success logs;
- decorative timelines with no prediction/observation distinction;
- audit logs that hide unresolved epistemic state;
- animations whose direction implies truth not established by evidence.

The Web witness trace in alpha is an experiment surface, not a frozen component API.
