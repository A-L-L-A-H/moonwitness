# CRAYON v0.8.0-alpha.1

**Release theme:** close the semantic loop through Witness, then prove the same meaning survives Web, Text, Agent, and Voice representations.

This is an alpha engineering checkpoint. It does not claim production security certification, stable Visual DNA, durable distributed execution trust, or long-term API compatibility.

## What this release adds

### Witness Loop
- Immutable temporal records for prediction, observation, reconciliation, witness, and retry assessment.
- Later evidence appends reconciliation history without rewriting historical prediction or witness truth.
- Semantic Snapshot projects temporal history with provenance/evidence identifiers.
- RIR carries temporal meaning without becoming an activity-feed component model.
- Inspector explains evidence chronology and retry safety.
- Web/Text representations expose witness state, uncertainty, and reconciliation explicitly.

### High-impact consequence policy
- Caller-declared low risk cannot downgrade high-impact or irreversible consequence.
- Unknown consequence is not equivalent to safe consequence.
- Commitment interaction remains derived from semantic resistance rather than styling choices.

### Representation physics
Existing gravity/distance/depth/trace are joined by:
- Disclosure — how much meaning must surface before commitment.
- Continuity — how much semantic orientation must survive a state/focus change.
- Momentum — whether committed/executing/external work remains visibly unresolved.

All physics values remain deterministic and explainable.

### Human interaction and accessibility
- Semantic traversal/focus ordering.
- Compact / standard / expanded semantic projection.
- Compact views may not hide critical uncertainty, consequence, authority requirements, or witness state.
- Uncertainty/witness semantics are not color-only.
- Web renderer retains exact semantic references as machine-readable DOM metadata.

### Multi-renderer invariance
New public packages:
- `allah-crayon-agent`
- `allah-crayon-voice`

The release set now contains eight public packages. Web, Text, Agent, and Voice are required to preserve the same critical truth, actionability, consequence, authority requirement, uncertainty, and witness claims. Rendering never grants authority.

### Stabilization
- Versioned semantic specification.
- Explicit Snapshot/RIR compatibility validation; unknown versions are rejected rather than silently reinterpreted.
- Public API classification and migration policy.
- Security threat model for forged evidence, authority escalation, stale execution, replay/ABA, renderer suppression, mutation, and secret leakage boundaries.
- Executable large-situation performance budget.
- Canonical package release-set manifest and internal dependency/version consistency validation.
- Token/import-aware RIR architecture guard avoids substring false positives while retaining prohibited-fixture coverage.

### Visual DNA calibration
This release does **not** freeze a design-token API. It adds falsification infrastructure instead:
- realistic semantic gravity calibration data across unrelated domains;
- representation audit criteria for truthfulness, proportional attention, orientation, consequence, explainability, accessibility, and witness persistence;
- witness-history criteria that reject generic activity-feed treatments that blur prediction/observation/current truth;
- admission criteria for any future stable design token.

## Cross-domain failure scenarios
The universal grammar is exercised against:
1. Banking — ambiguous transfer with retry blocked until reconciliation.
2. Files — recursive delete and restore-window stress.
3. Email — irreversible send with corrective follow-up as a new action/history record.
4. ERP — multi-stage approval with conflict.
5. DevOps — partial deployment, rollback, and reconciliation.
6. AI — proposal → human commitment → service execution → evidence-derived outcome.

Domain names are forbidden as special-case branches in the semantic planner.

## Release pipeline

Development commits on `dev` do not consume the self-hosted runner. The release boundary is `main`:

```text
dev → main
   ↓
living-crayon
   ├ verify release set
   ├ TypeScript + tests + falsification
   ├ performance budget
   ├ Lab production build
   ├ examples
   ├ pack/fresh-tarball smoke
   └ capture + commit real Lab screenshots
   ↓ success
publish-npm-alpha
   ├ build publish artifacts
   ├ idempotent npm publish
   ├ verify every package @alpha dist-tag
   └ fresh project install/import from npmjs.org
```

Publish success is not recorded until the real-registry smoke passes.
