# Formal Failure & Fault Recovery Matrix
**Application Execution Protocol (AEP)**
*Specification Version: 1.1.0-normative*

---

| Fault ID | Scenario | Expected State | Allowed Recovery | Forbidden Behavior | Test Strategy |
|---|---|---|---|---|---|
| **F01** | Connection drops before `RUN` is accepted by Gateway | Client: `SUSPEND`<br>Server: Clean socket drop | Client reconnects, resends `RUN` with original `idempotencyKey` | Creating multiple executions or failing silently | Drop socket immediately after client transmits `RUN` frame bytes |
| **F02** | Connection drops after `RUN` accepted, before client receives ACK | Client: `SUSPEND`<br>Server: `ACCEPTED` or `RUNNING` | Client reconnects, calls `RESUME`; Gateway replays `ACCEPTED` ACK and attaches to execution | Creating a 2nd execution or restarting work from scratch | Sever socket immediately upon server emitting ACK frame |
| **F03** | Connection drops while Execution is `RUNNING` | Execution continues in fabric;<br>Events buffered in session ring buffer | Client reconnects via `RESUME`; Gateway replays missed delta events | Terminating execution unless explicitly flagged non-durable | Kill transport mid-way through 5s streaming task |
| **F04** | Connection drops after Execution `SUCCEEDED`, before client receives result | Execution: `SUCCEEDED` in DB;<br>Result stored in `execution_records` | Client reconnects; Gateway returns cached final result immediately | Re-executing work or discarding completed output | Cut connection 1ms before emitting terminal `execution.completed` event |
| **F05** | Duplicate `RUN` frame received (Network retry) | Exactly 1 execution exists | Gateway returns reference/stream of existing execution | Double-inserting records or charging twice | Inject duplicate `RUN` frames with identical `idempotencyKey` |
| **F06** | Duplicate `DATA` frame received (Duplicate sequence) | Stream state unchanged | Receiver acknowledges duplicate sequence and discards payload | Appending duplicate chunk to payload buffer | Send duplicate sequence number on active data stream |
| **F07** | Delayed `ACK` (ACK arrives after retry timer) | Peer receives redundant frame, ACKs again | Receiver acknowledges redundant frame idempotently; no state corruption | Corrupting sequence pointer or crashing | Inject 2000ms artificial network delay on ACK frames |
| **F08** | Invalid `ACK` (ACK sequence higher than transmitted) | Protocol error detected | Session triggers state synchronization or emits `ACK_OUT_OF_BOUNDS` | Advancing stream window into unverified future | Emit ACK for sequence 99 when only sequence 5 was sent |
| **F09** | Out-of-order `DATA` frame received on reliable stream | Sequence gap detected | Frame held in reorder buffer until missing sequence arrives | Processing payload chunks out of order | Transmit sequence 3 before sequence 2 on same stream |
| **F10** | Session `RESUME` after Server Restart | Ephemeral ring buffer wiped; Session & Executions alive in SQLite | Gateway validates `resumeToken`, returns `HELLO(helloKind: WELCOME, resume: ACCEPTED/SYNC_SNAPSHOT)`, emits Authoritative State Sync | Forcing session destruction when a valid session remains within dormant TTL | Kill Fastify process, restart, and assert session resumes via State Sync |
| **F11** | Session `RESUME` after replay-window expiry (> 60s and within 24h dormant TTL) | Replay buffer unavailable; durable Session & Executions remain authoritative | Gateway returns `HELLO(helloKind: WELCOME, resume: ACCEPTED/SYNC_SNAPSHOT)` followed by authoritative state sync | Closing a valid session solely because its replay buffer expired | Delay reconnection beyond 65s and assert state sync, not `SESSION_EXPIRED` |
| **F11A** | Session `RESUME` after dormant TTL expiry (> 24h) | Session expired or revoked | Gateway returns rejected welcome response then `CLOSE(SESSION_EXPIRED)`; client starts clean session | Restoring an expired or unverified session | Delay reconnection beyond 24h and assert `SESSION_EXPIRED` |
| **F12** | Worker Fabric Node dies during execution | Execution orphaned on failed node | If idempotent, Gateway re-dispatches to healthy node; otherwise marks `FAILED` | Hanging client in permanent `RUNNING` state | Force kill worker thread during active execution |
| **F13** | Capability disappears during active session (Hot reload / Undeploy) | Capability absent from registry | In-flight execution runs to completion; new `RUN` rejected with `CAPABILITY_NOT_FOUND` | System panic or hanging requests | Unregister capability while client session remains open |
| **F14** | Bounded Stream Queue Overflow | Buffer limit exceeded (`maxBufferBytes`) | Backpressure policy activates (`BLOCK`, `DROP_EPHEMERAL`, or `FAIL_STREAM`) | Unbounded memory growth leading to process OOM | Flood receiver at 100 MB/s without reading buffer |
| **F15** | Malformed Frame (Corrupted bytes, bad magic) | Parse failure triggered | Frame dropped immediately; emit `PROTOCOL_VIOLATION`; close socket if magic corrupted | Executing buffer overrun or process crash | Transmit random fuzz bytes to gateway socket |
| **F16** | Oversized Payload (> 16 MB) | Bounds violation triggered | Stream terminated with `OVERSIZED_PAYLOAD` error; memory not allocated | Attempting `Buffer.alloc(2GB)` and crashing V8 | Send frame header with length set to `0xFFFFFFFF` |
| **F17** | Unsupported Protocol Version (Major != 1) | Incompatible version | Connection closed immediately with `PROTOCOL_VERSION_UNSUPPORTED` | Attempting to parse incompatible binary layout | Send frame with `protocolVersion = 0x02` |
| **F18** | Unsupported Capability Version (Semver mismatch) | Capability version mismatch | Gateway rejects `RUN` with `CAPABILITY_VERSION_MISMATCH` | Executing with incompatible input schemas | Dispatch `RUN` requesting capability version `99.0.0` |
| **F19** | Auth Token expires or refreshes during execution | Authentication refresh | Execution finishes under original authenticated context; subsequent `RUN` requires refreshed token | Halting active execution mid-flight unless revoked | Expire bearer token during long-running streaming execution |
| **F20** | Cancellation Race (`CANCEL` arrives during completion) | Execution finishes as `SUCCEEDED` or `CANCELLED` deterministically | If work completed and committed to DB, `SUCCEEDED` wins; client informed work completed | Entering undefined or corrupted state machine status | Fire `SIGNAL(CANCEL)` and `DATA(FIN)` concurrently |
